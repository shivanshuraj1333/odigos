# Memory profiling e2e (.NET + Node) — in-cluster certification

Proven on k3s: the odigos collector (built via `collector/Dockerfile.memprof-vendored`,
embedding the memory-profiling ebpf-profiler fork) runs as a privileged hostPID
DaemonSet, detects .NET/Node workload pods by /proc, and emits **symbolized**
allocation profiles attributed per workload.

Evidence (debug exporter): Node frames `churn`/`FastBuffer`/`createUnsafeBuffer`,
.NET frames `Program.Main`/`System.Byte[]`; ResourceProfiles tagged
`process.executable.path=/usr/local/bin/node` and `/app/.../net8.0/app`.

In production this pipeline is generated by the autoscaler (profiling.memory with
languages.dotnet/node) and exports OTLP → gateway → Pyroscope instead of debug.
DaemonSet must mount `/sys/kernel/debug` + `/sys/kernel/tracing` for the CPU tracer.
